# Confirmed Tree Arcade streak milestones

Alerts: 3, 7, 14, 30 days and every additional 30 consecutive days. One lifetime announcement per wallet and milestone, with confirmed UTC check-in dates across month boundaries. Sign-in, refresh, game launches without a saved check-in, and paid attendance recovery do not create streak milestones. Recovery dates are excluded from streak length.

A private insert trigger captures a milestone in the same transaction as the confirmed check-in. It never edits attendance, sessions, badges, quests, or payment data. Unique(wallet,milestone) prevents repeated milestones after a broken/rebuilt streak. No historical records are replayed or seeded. New rows after migration only. Database RPC is SECURITY INVOKER and executable only by service_role; outbox RLS is enabled and no anon/authenticated access is granted.

The isolated GET-only Netlify feed uses existing Functions-scoped Supabase credentials. It returns only milestone IDs, dates, primary SuiNS names or a shortened wallet label, and badges captured in the same database transaction as that check-in milestone (the discovery migration handles the distinct clock_timestamp values). Full wallets, sessions, payment information and service keys are never returned. Badge labels match the Arcade's current monthly rank branding; a milestone itself never creates a badge.

Railway's existing NFTree notifier reads the feed every 30 seconds with a five-minute overlap to catch late commits. Milestone delivery IDs persist on the existing /data state volume. A pending reservation is saved before sending; confirmed API rejection permits retry, while ambiguous timeout/crash remains reserved (uncertain/sending) to prevent duplicate announcements. Reconcile that Telegram message before manually clearing any reservation. Existing game alerts and weekly schedule are unchanged. Check-in milestones are recognition, not prize eligibility.

Validation: PostgreSQL-compatible PGlite 0.3.14 tests run the actual migration and cover 3/7/14/30/60/90, gaps, month crossings, paid recovery, transaction rollback, repeated/rebuilt milestones and role protection. Feed tests cover privacy, SuiNS, cursor pagination, errors and write rejection. Bot fixtures cover approved thresholds, real-badge evidence, retries, persistent deduplication and late arrivals. 62 bot tests and 4 feed/database tests pass. The archived 38-function parity check passes before packaging. Publication preserves all live static files, all existing complete function records/configuration and five schedules; only a new isolated function is added.

To rerun database tests without changing app dependencies: run npm ci --prefix vendor/arcade-discovery-tests, then node --test tests/arcade-streak-database.test.mjs tests/arcade-streak-feed.test.mjs. Source/runtime package dependencies and lockfiles remain unchanged.
