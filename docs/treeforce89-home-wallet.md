# TREE FORCE home screen and Sui wallets

NFTree access now lives on the actual game home screen. The public title scene displays the title, enemies and Arborwing, with compact connection/verification controls in its lower panel. It registers no pointer, keyboard or gamepad start handlers. Only a verified session mounts playable gameplay. Verification launches the game directly; expired, denied, disconnected or switched-wallet sessions return to the public home. Paid continuation and its existing receipt recovery remain intact.

The former picker already discovered all installed Sui Wallet Standard wallets, but only showed detected wallets. Its incomplete dark theme allowed a light wallet row with unreadable text. The home screen now has a clearly labelled chooser: every detected Sui wallet gets a real Connect action, and missing Slush, Suiet, Nightly and Backpack choices have explicitly labelled **Get wallet** links to their publishers. Unknown compatible wallets are retained. Get-wallet links never masquerade as connection buttons. The dialog uses native focus containment/Escape behavior, explicit high-contrast labels, connection progress, cancellation/retry and a lock against duplicate requests.

The chooser uses the pinned SDK's `useWallets()` and `connectWallet({wallet})`, exactly the action used by its original built-in modal. Existing wallet configuration (`app/dapp-kit.ts`), SDK versions, dependency lock, NFTree proof/signature verification, transaction construction/signing, 20,000 TREE price, treasury, server handlers, schema and payment flags are unchanged. All 39 published backend package/provider/runtime records and all five schedules must match the actual live baseline `6ae56ffd12cc39baec9bc7b2` exactly. Only native game HTML/CSS and new native JavaScript assets change.

Primary references checked: the current Mysten Labs frontend-apps skill and React guide; the installed dApp Kit 2.1.41 connection, hook and theming docs; https://www.docs.sui.io/onchain-finance/asset-custody/wallets/self-custody; https://www.sui.io/get-started; https://slush.app/download; https://suiet.app/install; https://nightly.app/; https://backpack.app/downloads. The current Sui guide lists Backpack as a Sui wallet; Nightly and Suiet also describe their Sui support directly.

Validation includes 32 focused tests: multiple and missing wallet choices, publisher links, connecting the exact selected detected wallet, cancellation, duplicate clicks, public-home/verified-game rendering, denied ownership, and existing payment/receipt/Resume interactions. Wallet connection and ownership responses are controlled doubles in UI tests; hosted authentication and independent payment checks are run separately. The pinned native game build passes and asserts its original wallet configuration and lock byte-for-byte. Real wallet permission/holder testing remains user-operated; no payment was signed or submitted by the assistant.
