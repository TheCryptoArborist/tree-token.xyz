# Same-page TREE FORCE '89 sign-in — preview only

The game replaces its separate TREE account popup with a same-page modal. The wallet still presents its own approval UI. No iframe, browser redirect, extra TREE window, production migration, or real payment is introduced.

The central inline endpoint reuses createAccountService, the exact existing preview account namespace, alias resolution, nonce consumption, Mysten/viem signature verification, and parent/child session validation. Signatures are now bound to the configured game origin. A server-side authorize/exchange handoff returns the existing game-session token type. The game proxy stores it under the existing HttpOnly/Secure/SameSite cookie name; tokens and proof bindings are not returned to browser JavaScript. The previous popup endpoints remain intact for old tabs.

Existing accounts retain the same UUID when signing with the same wallet. The test CC ledger is neither edited nor reset. Different wallets are not merged. NFTree entitlement stays not-checked; signing in does not grant holder access, credits, or verified records. Sui Mainnet authentication and the existing two EVM testnet routes remain as before.

The game snapshots its active/paused scene, physics, and input state before opening the modal. Success, cancellation, and signature rejection restore only the state owned by this modal, never restarting the game. An already-paused continue dialog remains paused. A SIGN IN HERE control is available inside the credit dialog for expired/guest sessions. Late wallet responses after cancellation/account changes cannot complete sign-in. Dismissal is briefly locked during challenge creation and final server verification to avoid racing authentication cookie writes; connection/signature prompts remain cancelable from the panel.

Validation: 35 new local Node checks passed (14 central service, 8 game proxy, 13 wallet/pause/UI-source checks). Central tests use the existing account service with in-memory conditional-write storage and mocked signatures; game proxy tests mock its upstream. The preview build also runs the existing SDK signature tests. The actual new UI modules were exercised in an in-memory Chromium harness at 1200x900, 390x844, and 320x700: 21 scenario/viewport checks passed, covering success/cancel, rejection, delayed signature after cancel, account switching, EVM sign-in, and nested credit-dialog behavior. Wallets, HTTP responses, and Phaser interfaces were mocked. No live installed-wallet or full Phaser campaign acceptance is claimed; runtime outbound browsing was blocked.

Use https://deploy-preview-1--treeforce89.netlify.app/ for acceptance. Finish the current flight before refreshing to load the new build. On a fresh flight, open SIGN IN, select Sui, connect, sign the personal message, and confirm the same wave/score/lives resume with the existing account balance. Repeat Cancel before signing. When already signed in, sign out and back in using the same wallet. This does not spend test credits. Do not clear site data, load a new credit package, or use an immutable deployment hostname.

Only the paired preview branches are changed. No environment values, production branches, gameplay tuning, boss/background/abduction code, credit prices, or credit journal are changed. Real TREE payments remain disabled.
